# Evidence Source Pipeline V1

This integration turns the Evidence Gate classifier into a bounded source-to-receipt product path.

## Product layers

- `github_workflow_adapter.py`: deterministic GitHub Actions assessment policy.
- `drive_evidence_adapter.py`: deterministic Google Drive artifact identity policy.
- `unified_evidence_source_runner.py`: auto-selects the GitHub or Drive adapter from one normalized input.
- `live_source_collector.py`: accepts a supported GitHub or Drive URL, performs live collection under a frozen policy, normalizes the observation, and invokes the unified runner.
- `source_policy_registry.json`: frozen expectations. Live observations never create their own expected values.

## End-to-end path

```text
GitHub or Drive source
-> frozen policy
-> deterministic adapter
-> Evidence Gate
-> one result
-> one receipt
```

## Normalized runner

GitHub:

```bash
python unified_evidence_source_runner.py examples/live_github_pr7.json
```

Drive:

```bash
python unified_evidence_source_runner.py examples/live_drive_boot.json
```

Each command writes one result and one receipt.

## Live URL collector

GitHub PR:

```bash
python live_source_collector.py \
  "https://github.com/lbkapcsolat-dotcom/evidence-gate/pull/7"
```

Google Drive stored file:

```bash
export GOOGLE_OAUTH_ACCESS_TOKEN="..."
python live_source_collector.py \
  "https://drive.google.com/file/d/1Y965Pm3M7Ug7m5Ksyd7-FenDJFn57Pde/view?usp=drivesdk"
```

GitHub can optionally use `GITHUB_TOKEN`.

Credentials are read from environment variables only and are never written into the result or receipt.

## Policy boundary

The source policy registry is independent from the live observation.

Bad pattern:

```text
read current SHA256
-> declare current SHA256 to be expected
-> PASS
```

V1 rejects that pattern. Expected constraints are frozen before the live read.

## Fail-closed behavior

- unknown source shape -> error
- ambiguous normalized input -> error
- unknown URL host -> error
- unregistered policy -> error
- Drive connector unavailable -> insufficient
- confirmed missing Drive file -> contradicts
- verified Drive identity mismatch -> contradicts
- missing or unfinished GitHub workflow -> insufficient
- completed required GitHub workflow without success -> contradicts

## Claim ceiling

The pipeline can only support the narrow claim generated by the selected adapter.

It does not establish merge readiness, production readiness, runtime admission, certification, or global validity.
